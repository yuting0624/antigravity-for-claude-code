# 原理：自动委托是如何实现的

> 适用版本 0.27.0 · 宿主 pi coding agent · 大脑 GLM（zai-coding-cn）· 本地执行器 omlx / Ornith-1.5-35B-A3B-MLX-4bit

一句话：**“自动”= 扩展让委派的门槛降到一次工具调用，并让 GLM 从会话第一秒起就知道何时该委派、做完必须验收。决策永远在现场的 GLM 手里，苦力永远在本机的 Ornith 身上，质量关由前者对后者把关。**

它不是靠某个启动旗标或 if-else 路由器实现的——代码从不代替 GLM 决定“要不要委派”，只负责让它**随时能**委派（工具）、**知道何时该**委派（策略注入）、并且委派**成本极低**（结构化调用）。

## 总览：一条消息的生命周期

```
你敲下 pi
   │
   ▼
┌─ 启动加载（一次性配置的成果）──────────────────────────────┐
│ settings.json packages → 加载本包                          │
│   ├ extensions/antigravity-glm.ts    （扩展，注册钩子和工具）│
│   ├ skills/antigravity-glm/SKILL.md  （只有描述进系统提示）  │
│   └ prompts/*.md                     （变成 /agy-* 命令）    │
└────────────────────────────────────────────────────────────┘
   │
   ▼
┌─ 会话开始 ─────────────────────────────────────────────────┐
│ session_start 事件 → 健康检查通知（大脑/agy/omlx 探活）       │
│ defaultProvider/defaultModel → 本回合模型是 GLM             │
└────────────────────────────────────────────────────────────┘
   │
   ▼  你发出一条消息
   │
   ▼
before_agent_start 事件（扩展动手脚的地方）
   ├─ 首次触发：把 ROUTING_POLICY 追加进系统提示（每会话一次）
   └─ 输入命中批量启发式？→ 再追加一句 nudge（建议，非命令）
   │
   ▼
agent loop：GLM 综合策略 + 任务特征 + 工具描述，自己做盈亏平衡判断
   │
   ├─ 小活 / 判断密集 → 自己做（不委派）
   │
   └─ 批量 / 重复 / 高于盈亏平衡点 → 调用 delegate 工具
        │
        ▼
     execute()（确定性代码）
        │  拼 CLI 参数
        ▼
     scripts/agy-delegate.sh --backend local --digest "..."
        ├─ backend=local → exec local-delegate.sh
        │      ├─ tier fast/think → Ornith-1.5-35B-A3B-MLX-4bit
        │      ├─ python3 构建 JSON（安全转义）→ curl POST omlx
        │      ├─ HTTP 分类 → 退出码（10 配额/11 认证/12 超时/13 不可达/14 无此模型）
        │      └─ 内容(stdout) + LOCAL_USAGE(stderr)；--out 由 wrapper 落盘
        └─ backend=agy → agy CLI（--dir 读仓库、--yolo 授权、真实改文件、联网搜索）
        │
        ▼
     结果文本回到 GLM（失败附退出码对照表，GLM 可自行应对）
        │
        ▼
     验证关卡（策略规定的法定义务）：亲自跑测试/核对结论
        │
        ▼
     向你汇报
```

## 第 0 层：安装时发生了什么（一次性）

`package.json` 的 `pi` manifest 声明三样东西：

```json
"pi": { "extensions": ["./extensions"], "skills": ["./skills"], "prompts": ["./prompts"] }
```

`pi install <路径>` 把该路径写入 `~/.pi/agent/settings.json` 的 `packages` 数组。此后每次 `pi` 启动都会自动重新加载这三类资源——扩展用 jiti 直接执行 TypeScript，无需编译。

“大脑是 GLM”同样只是 settings 里的两个字段（无特殊启动命令）：

```json
"defaultProvider": "zai-coding-cn",
"defaultModel": "glm-5.3"
```

## 第 1 层：扩展向 pi 注册了什么（启动时）

工厂函数执行四个注册：

| 注册 | 作用 |
|---|---|
| `pi.registerTool({ name: "delegate", parameters: Type.Object({...}), execute })` | 委派工具：backend/tier/dir/yolo/digest/out/web/timeout 各参数的 JSON Schema 说明即文档 |
| `pi.registerTool({ name: "job", ... })` | 后台任务工具（start/list/status/result/cancel），仅交互式会话有意义 |
| `pi.on("session_start", ...)` | 快速健康检查 + 重置策略注入标志 |
| `pi.on("before_agent_start", ...)` | **自动委托的核心事件**：注入策略 + 批量 nudge |

关键点：注册完成后，`delegate` 对 GLM 而言和内置的 `read`/`bash` 没有区别——就是一个带完整参数说明的原生工具。**这是“低成本委派”的基础：GLM 不需要记命令行，调一个结构化工具即可。**

## 第 2 层：会话开始（你还没说话）

`session_start` 触发健康检查：大脑凭据（`ZAI_CODING_CN_API_KEY` 等）→ agy 是否在 PATH → 探活 `http://127.0.0.1:8000/v1/models`。结果以通知弹出供你确认三件套状态，然后重置 `policyInjected = false`。

## 第 3 层：一条消息进来后（核心机制）

### ① 注入路由策略（每会话一次）

扩展拦截 `before_agent_start`，首次触发时把一段 ROUTING_POLICY 文本追加到系统提示，内容包括：

- **执行器选型表**：agy = 能读写仓库/跑终端/联网的代理；local = 私密免费的纯生成器（无文件访问、写入靠 `--out`、搜索靠 `--web`）
- **何时委派**：批量/并行/重复、明显超过“规格+往返+验证”开销的工作；小活自己干
- **成本杠杆**：吃 digest 不吃原文、合批、`--dir` 让 agy 直读 AGENTS.md 与真实文件
- **验证义务**：绝不信任执行器自报的“全绿”，必须亲自在干净状态重跑门禁

之后每个回合不再重复注入（`policyInjected` 标志）。**这就是“自动”的第一半：GLM 从会话第一秒起就带着这套纪律工作，而你完全无感。**

### ② 批量任务 nudge（可选提醒）

同一事件里，扩展对你的原始输入跑约 40 条中/英/日短语的启发式匹配（“所有文件”“迁移”“生成测试”“scaffold”……）。命中且未显式提委派时，追加一句固定文案——结尾是 *"THE JUDGMENT IS YOURS"*：**这只是给 GLM 的提示材料，不是命令**。普通小修改完全不触发。

### ③ GLM 自己做盈亏平衡判断

agent loop 开始后，**决策者是 GLM，不是任何 if-else**。它综合策略文本 + 任务特征 + 工具描述里的警示（"Only delegate ABOVE the break-even"），得出计划，例如：

> “迁移整个模块 = 批量重复工作，高于盈亏平衡点 → 委派；规格我先写清楚 → 用 delegate 工具，backend=local（改配置涉密），digest=true”

这是有意的设计：上游项目实测过**全自动路由在小任务是净亏损**，所以架构上刻意把 break-even 判断留给模型逐任务裁量；代码只保证它“有能力委派、有知识判断”。

### ④ delegate 工具真正执行（从这里开始全是确定性代码）

```
execute() 拼 CLI 参数
    │
    ▼
spawn scripts/agy-delegate.sh --backend local --digest "...任务..."
    │
    ├─ backend=local → exec scripts/local-delegate.sh
    │      ├─ tier fast/think → 默认映射到 Ornith-1.5-35B-A3B-MLX-4bit
    │      ├─ --digest 给提示词追加"仅摘要"输出契约
    │      ├─ python3 构建请求 JSON（安全转义任意字符）
    │      ├─ curl POST http://127.0.0.1:8000/v1/chat/completions（Bearer key + --max-time 墙钟保护）
    │      ├─ HTTP 分类：429→10 配额 · 401→11 认证 · 404(含 model)→14 模型不存在 ·
    │      │             超时→12 · 连接拒绝→13 服务未启动
    │      ├─ 成功：LOCAL_USAGE token 统计走 stderr；内容走 stdout
    │      └─ --out：wrapper 把回复落盘（剥最外层代码围栏），期间没有任何东西被执行
    │
    └─ backend=agy → Antigravity CLI（代理式：--dir 读仓库、--yolo 授权、真实改文件、
                    Google/Vertex 搜索、内部子代理扇出）
```

所有工程难点都被封在这两个 wrapper 里：非 TTY stdout 丢失（stdin 重定向 `/dev/null`）、墙钟防挂死（超时杀进程并归类为退出码 12）、错误分类信号行（`AGY_SIGNAL` / `LOCAL_SIGNAL`）、digest 尺寸警告——GLM 完全不用操心这些。

两个后端共用一套退出码空间，所以上层（job 工具、GLM 的应对逻辑）只需学一次：

| 码 | 含义 | 典型应对 |
|---|---|---|
| 10 | 配额/限流 | 稍后重试 / 降并发 |
| 11 | 认证失败 | 查 key / 重新登录 |
| 12 | 超时 | 加大 timeout 或缩小任务 |
| 13 | 执行器缺失 | 启动 omlx / 安装 agy |
| 14 | 模型不存在 | 换模型名 / 改档位映射 |
| 15 | 权限被拒（仅 agy） | permissions.allow 规则或 --yolo |

### ⑤ 结果回到 GLM → 强制验证

`execute()` 把 stdout + stderr 摘要 + 退出码组装成文本返回；失败时附上上面的对照表，GLM 能自行应对（如 14 就换模型重试）。

成功也不算完——注入的策略里写着**验证是指挥者的法定义务**，GLM 会亲自跑生成的测试、核对评审结论，然后才向你汇报。（实测场景 A 中本地模型生成的 60 条断言里有 2 条算术自相矛盾——正是这一层拦下来的。）

## 为什么这样设计（而不是全自动路由）

| 设计选择 | 理由 |
|---|---|
| 判断留在 GLM，代码只投料 | 上游实测：低于盈亏平衡点的自动路由是**净亏损**（往返开销 > 收益）。break-even 必须逐任务裁量 |
| 委派收敛为一个工具 | pi 不给包挂 PATH；工具调用比拼命令行更不易错，参数 schema 即使用说明 |
| 两后端共用退出码/契约 | 上层只需学一次；“换后端”对 GLM 只是改一个参数 |
| digest 契约内置于 wrapper | 吃摘要不吃原文是最大成本杠杆——与其靠提示词自觉，不如默认机制兜底 |
| 验证写进注入策略 | 本地模型的产出是高质量初稿而非成品（实测 2/60 坏断言）；指挥者对正确性负全责 |

## 一句话总结

> **“自动委托”= 扩展把委派的门槛降到一次结构化工具调用，并让 GLM 从会话第一秒起就带着“何时该委派、如何省着委派、做完必须验收”的纪律工作。判断在现场的大脑（GLM），产量在本机的引擎（omlx/Ornith），质量关由前者对后者把关——而这一切在你敲下 `pi` 的那一刻就已全部就位。**
