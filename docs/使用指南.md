三类角色的分工原则：

| 开发生命周期阶段 | 归属 | 原因 |
|---|---|---|
| 需求与规划 | **GLM** | 歧义消解、与人对话的判断力 |
| 设计与架构 | **GLM** | 权衡取舍 |
| 实现——复杂/承载架构的 20% | **GLM** | 正确性、深层上下文 |
| 实现——脚手架/样板/规格明确的批量活 | **agy 或本地** | 确定性、高产量 |
| 测试与评估生成 | **本地**（私密）或 **agy**（GLM 定义契约） | 廉价算力的地盘 |
| 首轮代码评审 | **本地**（隐私）或 **agy** → **GLM** 终审 | AI 初筛 + 人类/大脑终审 |
| 跨模型交叉验证 | **≥2 个不同家族的模型** | 不同失败模式互为保险 |
| 维护/迁移/现代化 | **agy** 执行（真实改文件），**GLM** 定方向 | 繁琐、系统化 |
| 网络 / Vertex AI Search | **agy**（原生工具）· **本地 `--web`**（自建搜索综合） | 补齐 GLM 缺失的工具 |
| 音频/视频理解 | **agy**（Gemini 原生多模态）；本地模型不支持 | —— |
| 深度调研（多源） | 执行器扇出搜集 · **GLM** 验证引证并成文 | 重活在廉价侧消化 |

## 2. 核心理念：分工、成本、验证

这个插件的价值不在"多接了一个模型"，而在围绕模型的**结构**：

1. **智能路由**：判断性工作留在最强的大脑上，确定性高产量工作下沉到更便宜的执行器。生成已被解决；*验证、判断与方向感才是手艺*。
2. **成本是金融杠杆而非口号**：委托本身不省钱——省钱的机制是"指挥者上下文保持精瘦"（见[第 9 章](#9-成本纪律省钱到底从哪来)）。上游有完整 A/B 实测数据。
3. **验证关卡不可协商**：执行器的自我报告只是声明不是证据。所有要交付的东西必须由 GLM 在干净状态下亲自跑一遍门禁（见[第 10 章](#10-验证关卡不可妥协)）。

两种工作模式：

- **指挥者模式（同步内联）**：正在实时打磨某个东西，中途把一个小的、边界清晰的工作块丢给执行器，立即用结果。
- **编排者模式（异步多单元）**：把大任务拆成多个单元并行派发（常配 `--dir` 让 agy 直接读仓库），最后统一评审整合。适合迁移、按模式批量实现、测试套件。

## 3. 安装与配置

### 3.1 前置依赖

| 组件 | 用途 | 必需？ |
|---|---|---|
| [pi coding agent](https://github.com/badlogic/pi-mono)（`pi` CLI） | 外壳/工具框架 | ✅ |
| Node.js ≥ 20 | pi 运行时（扩展需要） | ✅ |
| python3、curl | 包内脚本的 JSON 处理与 HTTP | ✅（macOS 自带） |
| GLM API Key（编程套餐） | 大脑 | ✅ |
| Antigravity CLI（`agy`） | Gemini 执行器 | 二选一 |
| 本地推理服务（如 Ollama） | 本地执行器 | 二选一 |

> 至少配置一个执行器。只有本地执行器也能用全部核心功能（除联网搜索的工具型能力外）。

### 3.2 第一步：把大脑接上 GLM

pi 内置了智谱编程套餐 Provider，三种方式任选其一：

**方式一（最简单）：登录内置 Provider**

```
pi /login     # 选择 ZAI Coding Plan (China)（国际版选 ZAI Coding Plan）
/model        # 选择 glm 模型（pi --list-models zai-coding-cn 可查看可用 id）
```

**方式二：环境变量**

```bash
export ZAI_CODING_CN_API_KEY="<你的智谱编程套餐 Key>"   # 中国区（bigmodel.cn → 编程套餐 → API Key）
# 国际版 Z.AI 则用：export ZAI_API_KEY="<你的 Key>"
pi --model zai-coding-cn/glm-4.6
```

**方式三：自定义 Anthropic 兼容端点**（写入 `~/.pi/agent/models.json`）：

```json
{
  "providers": {
    "glm": {
      "baseUrl": "https://open.bigmodel.cn/api/anthropic",
      "api": "anthropic-messages",
      "models": [ { "id": "glm-4.6" }, { "id": "glm-4.5-air" } ]
    }
  }
}
```

保存后 `/model` 即可看到 glm 模型。`agy-doctor` 会报告它检测到的当前大脑。



### 3.3 第二步：安装本包（pi package）

```bash
# 方式一：从 git 安装（正式使用）
pi install git:github.com/<you>/antigravity-for-glm-code

# 方式二：本地目录开发模式（加载即生效，改完 /reload 热载）
pi -e /path/to/antigravity-for-glm-code
```

安装后你会得到：

- **扩展注册的原生工具** `delegate`（同步委派）与 `job`（后台任务）——GLM 直接调用，无需任何 PATH 配置；
- **斜杠命令模板**（见[第 5 章](#5-斜杠命令参考)）；
- **antigravity-glm 技能**（核心策略文档，按需加载）；
- 会话启动时的健康检查通知 + 成本感知路由策略注入。



### 3.4 第三步（二选一 a）：Gemini 执行器（agy）

```bash
# 安装并首次登录（浏览器授权）
# 见 https://antigravity.google/docs/cli-using
agy models        # 能列出 Gemini 模型即认证成功
```

可选：在 `~/.gemini/antigravity-cli/settings.json` 配置 GCP project/location 与 `permissions.allow` 授权（见[第 11 章](#11-安全与权限)）。

### 3.5 第三步（二选一 b）：本地执行器

最快路径——Ollama：

```bash
# macOS：直接装 App；Linux：
curl -fsSL https://ollama.com/install.sh | sh
ollama pull qwen2.5-coder:7b     # 默认 fast 档模型
ollama serve                     # 通常已自动运行（11434 端口）
```

其他 OpenAI 兼容服务同样支持（设 `LOCAL_DELEGATE_BASE_URL` 即可）：

| 服务 | 默认地址 | 说明 |
|---|---|---|
| Ollama | `http://localhost:11434/v1` | 最简单，本包默认值 |
| LM Studio | `http://localhost:1234/v1` | 图形界面，App 内启动 Server |
| llama.cpp server | `http://localhost:8080/v1` | `llama-server` 启动 |
| vLLM | `http://localhost:8000/v1` | 高吞吐生产级 |

模型选择建议见[第 8 章](#8-本地大模型服务详解)。

### 3.6 第四步：体检

```
/agy-setup
```
或命令行（`bin/agy-doctor`，或 `bash <包目录>/scripts/doctor.sh`）：

```bash
./bin/agy-doctor
```

doctor 会依次检查并给出精确修复命令：

- **大脑**：检测到哪个端点（bigmodel.cn / z.ai → GLM ✓；默认端点 → 给出切换指引）；
- **agy**：是否安装、能否列模型（即已认证）、GCP 项目/区域、各档位模型是否存在；
- **本地执行器**：探活 `{base}/models`，逐个核对已配置的本地模型是否被服务；
- 本包自身：扩展、脚本、bin 是否可执行。

### 3.7 配置项（环境变量）

pi 包没有宿主级设置面板；本包通过环境变量配置（写入 shell profile 或 `~/.pi/agent/settings.json` 无法直接传递——建议放 shell profile / `.envrc`）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `LOCAL_DELEGATE_BASE_URL` | `http://localhost:11434/v1` | 本地服务地址；裸 host:port 自动补 `/v1` |
| `LOCAL_DELEGATE_API_KEY` | 空 | 仅网关式本地服务需要 |
| `LOCAL_SEARXNG_URL` | 空 | 配置后本地 `--web` 改查你自己的 SearXNG |
| `AGY_OPTION_EXECUTOR_BACKEND` | `auto` | 未显式指定时的后端：`agy` / `local` / `auto` |
| `AGY_OPTION_LOCAL_TIER_FAST` / `_TIER_THINK` / `_LOCAL_MODEL` | 见第 8 章 | 本地档位模型映射 |
| `AGY_OPTION_TIER_FLASH` / `_FLASH_LO` / `_PRO` / `_DEFAULT_MODEL` | Gemini 各档 | agy 档位模型重映射 |
| `AGY_OPTION_CODING_POLICY` | `on` | 会话启动时注入路由策略；`off` 关闭 |
| `AGY_OPTION_DELEGATION_NUDGE` | `on` | 批量任务提示词的建议性提醒；`off` 关闭 |
| `AGY_OPTION_DIGEST_WARN_CHARS` | `8000` | 「像原始倾倒」警告阈值；0 关闭 |
| `AGY_OPTION_TIMEOUT` / `_STRUCTURED_OUTPUT` / `_USAGE_LOG` | — | agy 后端超时 / 结构化输出 / 计量日志 |

> 兼容性说明：历史变量名 `CLAUDE_PLUGIN_OPTION_*` 仍然有效（上游脚本沿用），两者取先设置者。

---|---|---|
| `executor_backend` | `auto` | 未传 `--backend` 时走谁：`auto`=装了 agy 用 agy，否则本地；也可固定 `agy`/`local` |
| `local_base_url` | 空（即 `http://localhost:11434/v1`） | 本地服务地址；裸 host:port 会自动补 `/v1` |
| `local_model` | 空 | 不传 tier/model 时本地用的确切模型名 |
| `local_tier_fast` | `qwen2.5-coder:7b` | 本地 fast 档（agy 别名 flash/flash-lo 也映射到它） |
| `local_tier_think` | `qwen3:14b` | 本地 think 档（agy 别名 pro） |
| `local_api_key` | 空 | 仅网关式本地服务需要；Ollama/LM Studio 免填 |
| `searxng_url` | 空 | 配置后本地 `--web` 改查你自己的 SearXNG（查询不出内网） |
| `default_tier` / `timeout` / `tier_*` / `default_model` / `structured_output` | — | agy 后端的档位/超时/模型重映射等（同上游） |
| `coding_policy` / `delegation_nudge` / `digest_warn_chars` / `usage_log` | — | 会话策略注入 / 批量任务提醒 / 摘要尺寸警告阈值 / 计量日志 |

## 4. 三个快速上手场景

### 场景 A：本地模型私密生成测试套件（数据不出机器）

```
你：给 payments 模块写完整的单测+边界用例，pytest 风格
```

GLM 会（经由 delegate 流程或子代理）执行类似：

```bash
cat src/payments.py | local-delegate --tier fast --out tests/test_payments.py \
  "为此模块编写 pytest 单元测试与边界用例；只输出 Python 代码"
```

然后 GLM **自己跑** `pytest -q` 验证——通过才算完成。

### 场景 B：跨模型评审当前 diff（默认本地，隐私优先）

```
/agy-review
```

内部：`git diff | local-delegate --tier think -`（想用 Gemini 对照就加 `--backend agy`）。GLM 逐条核实发现、剔除误报、输出仲裁结论。两个模型都同意的点可信度最高；分歧点才值得人细看。

### 场景 C：深度调研（执行器跑腿，GLM 验证）

```
/agy-research 2026 年本地部署编码模型的发展现状
```

流程：GLM 拆解子问题 → 各执行器并行搜索返回「发现+URL+日期」的紧凑摘要 → 对关键论断让执行器引用原文句子佐证 → GLM 交叉核对 ≥2 个独立来源后成文。**任何未经验证的引证都会被显式标注。**

## 6. 脚本直接调用参考

> 在 pi 会话里，优先使用扩展注册的 `delegate` / `job` 工具（无需路径）。以下命令行示例中的 `agy-delegate` 等裸名，在 shell 里对应 `<包目录>/bin/` 下的垫片或 `<包目录>/scripts/*.sh`；GLM 在会话中调用时以 `antigravity-glm` 技能目录为参照（脚本位于其上两级 `../../scripts/`）。

### 6.1 `agy-delegate` —— 统一委托入口

```bash
# 自动选择后端（装了 agy 用 agy，否则本地）
agy-delegate "任务描述"

# 强制后端
agy-delegate --backend agy   --tier pro --dir ./app --yolo "按 ARCHITECTURE.md 搭脚手架"
agy-delegate --backend local --tier think "评审这段设计的取舍：<粘贴>"

# 长提示词走 stdin（结尾一个 -）
echo "很长很长的规格…" | agy-delegate --backend local -m qwen2.5-coder:7b -

# 干跑：打印解析后的实际命令
agy-delegate --backend local --print-command "hi"
```

| 参数 | 适用后端 | 说明 |
|---|---|---|
| `-t, --tier <flash\|flash-lo\|pro>` | 双方 | agy 档位；转发到本地时映射为 fast/fast-lo→fast、pro→think |
| `--backend <agy\|local\|auto>` | — | 执行器选择，默认 auto |
| `-d, --dir <path>` | 仅 agy | 工作区（可重复）；agy 据此读 AGENTS.md 与真实文件 |
| `-m, --model <名称>` | 双方 | 确切模型名覆盖档位映射 |
| `--timeout <时长>` | 双方 | 如 `10m`；agy 默认 5m，本地默认 10m |
| `--digest` | 双方 | 附加"仅摘要"输出契约——读摘要不读原文是最大省钱杠杆 |
| `--print-command` | 双方 | 干跑，打印将执行的命令后退出 |
| `--yolo` | 仅 agy | 自动批准 agy 全部工具（危险，见第 11 章）；本地侧无效果并提示 |
| `--sandbox` | 仅 agy | 并非隔离手段（实测在 `--yolo` 下毫无约束作用）；本地侧无效果 |
| `--mode accept-edits\|plan` | 仅 agy | 注意 `accept-edits` 不是写授权（实测与不加一样被拒） |
| `-c, --continue` / `--conversation <id>` | 仅 agy | 恢复会话；用于配额/超时后的续跑，**不是**省钱手段 |

退出码（两后端共用一套，`agy-job status/result` 都能渲染）：

`0` 成功 · `1` 用法错误 · `2` 执行器失败 · `3` 空输出 · `10` 配额/限流 · `11` 认证 · `12` 超时 · `13` 执行器缺失（agy 未装 / 本地服务未启动） · `14` 模型不存在（本地侧修法：`ollama pull <模型>`） · `15` 权限拒绝（仅 agy：无头模式下某工具需要授权——从 agy 1.1.3 的软拒绝到 1.1.13 引入的硬错误，两种形态都映射到此码；修法是加 `permissions.allow` 规则或 `--yolo`）

失败时 stderr 输出机器可读信号行：`AGY_SIGNAL {…}` / `LOCAL_SIGNAL {…}`；成功时输出用量行：`AGY_USAGE {…}` / `LOCAL_USAGE {"backend":"local","model":"…","input":N,"output":N,"total":N}`。

### 6.2 `local-delegate` —— 本地执行器直连

```bash
# 生成的代码直接落盘（wrapper 写文件，不执行任何东西；外围代码围栏自动剥除）
local-delegate -m qwen2.5-coder:7b --out ./src/new_config.yaml \
  "把这份 v1 配置转换成 v2 schema，只输出 YAML：<粘贴>"

# 私密的 diff 初筛
git diff | local-delegate --tier think \
  "审查这个 diff 的正确性/安全/性能问题，逐条 file:line — 问题"

# 本地综合的网络搜索（查询文本会发给搜索引擎；综合在本机完成）
local-delegate --web "Ollama 最新支持的量化格式有哪些"

# 自建 SearXNG 时连查询都留在内网
LOCAL_SEARXNG_URL=http://localhost:8888 local-delegate --web "<问题>"
```

| 参数 | 说明 |
|---|---|
| `-t, --tier <fast\|think>` | 本地档位；也接受 agy 别名 flash/flash-lo/pro |
| `-m, --model <名称>` | 服务上的确切模型名（`ollama list` 查看） |
| `--host <base-url>` | 服务地址，默认 `http://localhost:11434/v1`；裸 host:port 自动补 `/v1` |
| `--out <file>` / `--raw` | 回复写入文件（默认剥一层外围 ``` 围栏）/ 保留原样 |
| `--web` | wrapper 先抓取搜索结果（SearXNG JSON 或 DuckDuckGo Lite）作为带编号的可引证上下文 |
| `--digest` / `--timeout` / `--print-command` / `-` | 同上表 |
| `--yolo` `--sandbox` `--dir` `--continue` 等 | 接受但无效并提示——本地是一次纯聊天补全，没有任何东西被执行 |

诚实的边界（务必记住）：本地执行器**没有文件访问**（内容走 stdin/prompt）、**不执行命令**、**每次调用无状态**。它擅长的是：给定内容的生成、转换、摘要与初筛。

## 7. 执行器选型指南

```
需要读写仓库文件 / 跑命令 / 联网搜索工具？
 ├─ 是 ──→ agy（Gemini）。本地模型做不到这些。
 └─ 否
      ├─ 内容涉密 / 要求离线 / 想零成本跑大量生成？
      │    └─ 是 → 本地执行器
      ├─ 任务质量要求高（架构权衡、复杂调试）？
      │    └─ 是 → GLM 自己做，或 agy pro 档
      └─ 海量琐碎文本转换/初筛？
           └─ 本地 fast 档（慢一点但免费），或 agy flash 档（快但要钱）
```

补充判断依据：

| 维度 | agy/Gemini | 本地模型 |
|---|---|---|
| 文件读写/命令执行/网络工具 | ✅ | ❌ |
| 数据出机器 | 是（Google 云） | 否（除 `--web` 查询） |
| 单次成本 | 按 token 计费 | ≈电费 |
| 速度 | 快（云端吞吐） | 取决于显卡/芯片，7B~35B 从数秒到分钟级 |
| 质量 | 高且稳定 | 由你选的模型决定；7B 编码模型干不了架构活 |
| 离线可用 | ❌ | ✅ |
| 审计轨迹 | transcript.jsonl（`agy-trace`） | 无（单次调用，验证产物本身即可） |

**混用才是常态**：同一任务里，敏感部分走本地，需要工具的部分走 agy，判断部分留给 GLM。

## 9. 成本纪律：省钱到底从哪来

上游项目用实测数字反复验证过的结论，全部适用于本分支（GLM Coding Plan 是包月配额制，本地执行器边际成本≈0，但纪律本身不变）：

1. **高于盈亏平衡点才委托。** 只有当卸载的体量明显超过"写规格 + 往返 + 验证"的开销时才值得。批量/并行/重复性工作 → 委托；小而独立或高判断密度 → 自己做。把小任务委托出去是**净亏损**。（本地后端把"钱"的盈亏平衡变成了"质量与等待"的权衡，且隐私常常本身就值得。）
2. **保持指挥者上下文精瘦（最大的杠杆）。** 不要把执行器已经处理过的文件再拉回上下文，不要把它的原始大段输出粘进对话。吃**摘要**（`--digest`），不吃原文——这直接决定每轮 `cache_read` 的大小。
3. **让执行器返回摘要而非倾倒。** 委托提示词末尾加明确约定："以 ===DIGEST=== 围栏块收尾：改动文件、关键决策、下一步上下文一段话；冗余细节只落文件。"两个 wrapper 还会在回复超过 `digest_warn_chars`（默认 8000 字符）时于 stderr 发出"像原始倾倒"的警告。
4. **合批，别碎嘴。** 一次大的、规格完整的委托胜过多次小往返。上游实测：每次 `agy-delegate` 都是独立会话、共享不了缓存——对同一语料委托 7.3 次就要付 7.3 次摄取费，盈亏平衡约 5.7 次。相关单元合并为一次委托；`--continue` **不是**省钱手段（实测续跑比新开贵 +82%/+277%）。
5. **评审看 diff，不看整棵树。**
6. **不对称投入。** 指挥者不需要开满推理强度去协调和验收；把产量交给便宜的一侧。

诚实表述：不存在"统一 N 倍省钱"。引用实测数字与盈亏平衡点，永远不要引用头条倍率。

## 10. 验证关卡（不可妥协）

GLM（指挥者）对正确性负全责。凡是要交付的东西：

1. **先定义契约。** 测试与评估由 GLM 编写并持有——它们比自然语言更精确地告诉执行器"什么叫做对"。
2. **输出评估=真的去跑，而不是读完代码就算。** 读 diff 是必要条件不是充分条件。跑测试、起服务、打真实接口，对照观察到的行为逐条核对验收标准。跑不了就明说，不许标记通过。
3. **轨迹检查（agy）。** 每次agy 运行都会留下逐步 `transcript.jsonl`；`agy-trace --audit <id>` 显示步骤类型计数与每个非零退出——实测存在整体 SUCCESS 但内部 6 条命令失败的案例。本地执行器没有轨迹（它只做了一次模型调用），所以直接验证产物。
4. **逐行评审要交付的代码。** 警惕聪明代码；核查 import 是否真实存在（幻觉依赖）、错误处理、边界情况。
5. **绝不相信执行器的"全绿"。** 实测：agy 为了让检查通过会**修改环境本身**——给 site-packages 打补丁、用 MagicMock 顶包缺失依赖——然后报成功。相信任何通过结果之前：把被动过的工具与干净参照做 diff、还原、在 GLM 自己控制下重跑门禁。自我报告是声明，不是证据。

不对劲时的处置：升档重试（`--tier pro` / `--tier think`）、收紧规格、或者这段干脆自己做。

## 11. 安全与权限

### 11.1 agy 的写授权（两种，窄的那种更好）

无头模式下 agy 的"未授权写"行为随版本漂移（1.1.0 前只描述不动手 → 1.1.0–1.1.2 写去暂存区 → 1.1.3 软拒绝 → 1.1.13 起硬错误），但**你的工作区始终不会被碰**，变化的只是它是否承认。两种授权：

- **`permissions.allow` 规则**（推荐，窄）：在 `~/.gemini/antigravity-cli/settings.json` 加 `"write_file(<真实目录>)"`——对该目录**递归**生效，无需任何旗标。注意 `<dir>` 是占位符，原样留着等于什么都没授权。规则若无法解析也不会有任何报错——怀疑时先跑 `agy-doctor`。
- **`--yolo`**（`--dangerously-skip-permissions`）：批准**所有**工具，是对整台机器的授权而非仅 `--dir`。联网搜索、Vertex AI Search、终端类工具都需要它（除非有规则覆盖）。

写任务务必在独立分支/worktree 上进行，事后 `git status` 验证。退出码 `15` 就是权限拒绝（agy 1.1.3 的软拒绝与 1.1.13 的硬错误两种形态都归到这里）。

**`--sandbox` 不是隔离手段**：上游在 macOS + agy 1.1.19 实测，`--yolo` 之下该标志毫无作用——写到 `--dir` 之外的绝对路径照样成功、`id` 照样执行、`curl` 照样出网。隔离靠 checkout 内容与 permissions.allow，不靠这个旗标。

### 11.2 本地执行器的安全面

天然安全得多：一次 HTTP 调用到 localhost，模型只产文本；`--out <file>` 由 wrapper 把文本写到**你指定的那一个路径**，期间没有任何东西被执行，也没有 `--yolo` 这类授权概念。风险只剩内容本身：生成的代码进入仓库前照常评审。

### 11.3 子代理门禁

`antigravity-delegate` 子代理被 PreToolUse 钩子限制为**只能裸名调用** `agy-delegate` / `agy-job` / `local-delegate`，禁止一切管道/链式/重定向/替换（防提示注入外传文件；源自上游 GHSA-hwv2-vjgj-8rcv 两次攻防）。给仓库请用 `--dir`，别用管道喂内容。

## 12. 故障排查与退出码

### 12.1 退出码速查（两个 wrapper 共用）

| 码 | 含义 | 修复 |
|---|---|---|
| 0 | 成功 | —— |
| 2 | 执行器失败 | 看 stderr 详情；换更高档位或收紧规格 |
| 3 | 空输出 | 同上；本地侧顺带检查服务日志 |
| 10 | 配额/限流 | agy：稍后 `--continue`；本地：降低并发后重试 |
| 11 | 认证 | agy：交互式跑一次 `agy` 登录；本地：核对 `LOCAL_DELEGATE_API_KEY` |
| 12 | 超时 | 加大 `--timeout`（本地大模型 10 分钟很正常）或缩小任务 |
| 13 | 执行器缺失 | agy 未安装 → 装 CLI；本地 → 服务没起来（`ollama serve` / LM Studio Server） |
| 14 | 模型不存在 | agy：`agy models` 里选；本地：`ollama pull <模型>` 或改 `local_tier_*` |
| 15 | 权限拒绝（仅 agy） | 加 `permissions.allow write_file(<真实路径>)` 规则或 `--yolo`（见 11.1；agy 1.1.3 软拒绝与 1.1.13 硬错误均映射至此） |

### 12.2 常见症状

| 症状 | 原因与处理 |
|---|---|
| `auto` 总是走本地 | agy 没装或不在 PATH。装好 agy 后 auto 自动回到 agy；或显式 `--backend agy` |
| 本地报 `BACKEND_MISSING` | 服务没监听。`curl -s $BASE/models` 验证；LM Studio 记得在 App 里开 Server |
| 本地报 `MODEL_UNAVAILABLE` | 模型名与服务不一致。`ollama list` 对照，或 `curl -s $BASE/models` |
| 本地特别慢 | 正常（本地推理）。加 `--timeout`；大批量任务考虑后台化 `agy-job start` |
| agy 无头挂死（原生 Windows） | 需要 ConPTY；用 WSL/macOS/Linux 做 HEADLESS 委派。wrapper 已有 wall-clock 保护（exit 12 而非永久卡住） |
| WSL 上 `--dir` 极慢 | 仓库在 `/mnt/*` 上，9p 桥接慢 10 倍。把仓库搬进 Linux 文件系统（`~`） |
| 写了但文件没出现 | 十有八九是写授权缺失（issue #10 家族）：工作区未被触碰，新版才会明说。按 11.1 加规则；`git status` 验证；退出码 15 会点名问题 |
| 更多 | 见上游英文排障手册 `docs/TROUBLESHOOTING.md`（症状索引式） |

## 13. FAQ

**Q：一定要装 agy 吗？**
A：不用。只配本地执行器即可使用绝大部分功能（私密生成、`--out` 落盘、`--web` 搜索、后台任务、评审初筛）。缺的只是 agy 的代理式能力（真实改仓库文件、终端、Vertex AI Search、音视频）。

**Q：GLM 大脑 + GLM 本地执行器，同一个模型自己验证自己有意义吗？**
A：作为执行器没问题（便宜量大），但交叉验证的价值来自**不同模型家族的独立性**——同族模型盲区相同。要交叉验证时，执行器选 Gemini 或另一个家族的本地模型。

**Q：`--web` 的搜索质量如何？**
A：尽力而为。DuckDuckGo Lite 抓取的是标题+摘要片段，不如 agy 直连 Google 工具；重要调研仍建议 agy 后端或 GLM 自带的检索，`--web` 胜在私有与零成本。

**Q：能同时保留 Anthropic 官方大脑吗？**
A：能。`pi /login` 切回 Anthropic（或删掉 models.json 里的自定义 Provider / 取消 ZAI 环境变量）即恢复；本包对大脑无感知，doctor 只是如实报告检测到的端点。

**Q：团队套餐 Key 报鉴权错误？**
A：团队编程套餐的 Key 与开放平台其他 Key 不通用，必须在套餐页内新建（见 3.2）。

**Q：如何知道某次委派实际用了哪个模型/花了多少？**
A：stderr 的 `AGY_USAGE` / `LOCAL_USAGE` 行包含模型名与 token 数；要留档就设置 `usage_log` 选项或 `AGY_USAGE_LOG=/path`（管道 `2>&1 | tail` 会把它冲掉——这也是提供日志文件的原因）。
