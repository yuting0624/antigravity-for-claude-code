# 配合效果实测：GLM 大脑 + 本地 omlx 引擎（Ornith-1.5-35B-A3B-MLX-4bit）

> 实测日期：2026-08-24 · 版本 0.27.0 · 全部数据为真实运行记录

## 环境

| 角色 | 组件 |
|---|---|
| 指挥者 | GLM（pi coding agent 大脑；本次评测中由自动化脚本代行编排动作，回路本身完全真实） |
| 执行器 | 本机 **omlx** 引擎（`http://127.0.0.1:8000/v1`），模型 **Ornith-1.5-35B-A3B-MLX-4bit**（MoE，激活约 3B，MLX 4-bit，262k 上下文） |
| 链路 | pi 扩展注册的 `delegate` 工具 → `agy-delegate.sh --backend local` → OpenAI 兼容调用 |

引擎裸性能参考：单次短问答首响应 **0.79 秒**（34 tokens 总耗时 <1s）——A3B 架构 4bit 量化在 Apple Silicon 上非常快。

## 场景 A：私密生成测试套件（local 的主场）

**任务**：给定一个含多种边界情况的 `parse_duration` 解析模块，生成穷尽的 pytest 测试并落盘。

| 指标 | 数值 |
|---|---|
| 输出 | 14 个测试函数 / 参数化后 **60 个用例**，4081 字符落盘 |
| 用量 | 输入 280 tok · 输出 13,501 tok · 合计 13,781 |
| 耗时 | 256.5 s（≈53 tok/s） |

**验证关卡执行结果**（指挥者亲自跑）：首轮 58/60 通过。2 个失败均为**模型的算术自相矛盾**——注释断言"重复单位累加"，期望值却写成只算一次（`"2h2h"` 期望 7200，正确值 14400）；另发现它假定被测模块名为 `duration` 而非 `durations`。修正这 2 条错误断言 + 复制模块名后 **60/60 全绿**。

> 结论：产出质量高（边界覆盖完整：空串、无数字单位、尾随数字、非法字符、乱序混合单位、大数值全被覆盖），但**必须核实**——2 条坏断言若直接进仓库就是毒测试。这正是插件坚持「验证关卡不可协商」的原因。

## 场景 B：植入 bug 的 diff 初筛评审（隐私场景）

**任务**：一个 diff 中埋了 2 个真实 bug 和 2 处误导性标注（其中一处的注释故意撒谎），让本地模型做怀疑式初筛。

| 植入项 | Ornith 的判断 |
|---|---|
| BUG-2：`>` 改 `>=`，挡住全额提现 | ✅ 正确命中，推理无误（全额应合法返回 0） |
| BUG-3：`lru_cache(maxsize=None)` 用于可变配置 | ✅ 正确命中（过期风险 + 无界增长） |
| 误导项 1：注释谎称"删除了空列表守卫"（实际补丁是新增守卫） | ✅ **识破注释撒谎**，判定为严格改进而非回归 |
| 误导项 2：clamp 高边界的 `>=`（行为完全等价） | ✅ 正确论证等价、无行为差异 |

**4/4 判断全部正确，零误报。** 用量 9,919 tok，耗时 187.5 s。作为 35B-A3B 级本地模型，这个初筛质量足以承担「第一遍筛子」的角色；终审仍归指挥者。

## 场景 C：`--web` 本地搜索综合

**任务**："MLX 4-bit 量化在 Apple Silicon 上通常带来多少加速与内存节省？"（wrapper 抓取 DuckDuckGo 结果 → 本地模型综合）

结果：52.5 s 产出带 `[n]` 编号引证的结构化综述，且诚实标注了"这些数字无法精确钉死"及影响因素（量化层比例、group size、硬件世代、memory-bound vs compute-bound）。查询文本经公网 DDG；提示词、推理全部在本机。

## 综合结论

| 维度 | 表现 |
|---|---|
| 速度 | 短任务秒级；长生成 ~53 tok/s，可用 |
| 质量 | 测试覆盖完整、评审 4/4 且能识破误导、搜索综合有引证有分寸 |
| 成本 | 三轮合计 ≈2.4 万 token，边际成本 ≈ 0（电费级） |
| 隐私 | 除一次搜索查询外全程不出机器 |

**最佳实践（由实测印证）**：GLM 负责「拆解任务 → 写清楚规格 → 亲自验收」三件事；Ornith 负责产量。它的产出要当作**高质量初稿**而非成品——场景 A 里那 2 条坏断言就是活例子。分工成立时，这是一套零 API 成本、数据不出机器、且质量足够支撑日常工程辅助的组合。
